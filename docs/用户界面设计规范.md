# UI Design Guidelines

## 1. Objective

AllMyTools uses a consistent, flat desktop interface that is calm, compact, and task-focused. The visual foundation is warm neutral grayscale, fine structural rules, bold display typography, and small-area dopamine business identifiers. Every visible interface must work in light and dark themes. Red is exclusively reserved for errors and dangerous actions, never for ordinary business identity.

## 2. Token architecture

Tokens are defined in three layers. Components may consume semantic and component tokens but must not use primitive color values directly.

```text
Primitive tokens -> Semantic tokens -> Component tokens
```

Examples:

```text
color.gray.950 -> color.background.canvas -> dialog.background
space.4         -> space.control.paddingX   -> button.paddingX
radius.2        -> radius.control            -> input.radius
```

Token groups:

- color: neutral ramps, business identity colors, semantic foregrounds/backgrounds/borders, status colors
- spacing: a fixed spacing scale used for gaps and padding
- typography: font family, size, weight, line height
- dimension: control heights, icon sizes, layout widths
- radius: one shared 4px radius for ordinary UI; circular marks and avatars remain 50%
- elevation: borders and subtle shadows, not decorative floating surfaces
- motion: duration and easing with reduced-motion alternatives
- zIndex: documented layers for content, menus, dialogs, and notifications

## 3. Themes

Built-in light and dark themes override semantic tokens only. Primitive scales remain stable as source defaults; user color overrides are applied through the documented settings contract.

- Do not hard-code `#000`, `#fff`, or gray values in components.
- Use `color.text.primary`, `color.background.canvas`, `color.border.default`, and other semantic names.
- Maintain readable contrast for text, icons, focus rings, disabled controls, and selected states.
- All interactive controls use the neutral grayscale in both themes: primary and selected states use the theme's selected neutral surface with primary text, while focus rings remain gray; only destructive commands use the red semantic surface. Business identity uses lime, blue, amber, and violet only as small color marks, progress segments, or bounded object accents. Red is reserved for errors and dangerous operations; it must not be assigned to tools, projects, categories, or ordinary content.
- Status colors communicate meaning but must not be the only signal; pair them with text, icon, or shape where needed. Shared `StatusBadge` uses a neutral bordered surface with a small semantic square marker; `ProgressBar` uses the selected semantic tone for its value segment, with blue as the default informational tone. `InlineMessage` keeps a complete neutral border and a semantic marker, while errors retain the red edge and marker.
- User settings may override validated primitive and semantic color tokens only. Arbitrary CSS injection is not supported.

### 3.1 Token 包实现状态

`packages/design-tokens` 已实现三层 Token：原始 Token、语义 Token 和组件 Token。应用入口通过 `theme.css` 引入实际变量，启动页使用浅色/深色分段按钮切换 `data-theme`；该控件必须保留键盘焦点、`aria-pressed` 状态和减少动效支持。共享排版使用内置的 `Archivo`（展示与正文拉丁字形）和 `DM Mono`（日期、时间与辅助标签），中文由系统中文字体回退。基础灰阶采用暖白、炭黑和更清晰的结构线，标题层级使用更大的字号与更重的字重；`color.background.navigation` 与 `color.text.navigation` 在浅色主题解析为浅色轨道/深色文字，在深色主题解析为深色轨道/浅色文字；一级导航悬停与选中态使用专用语义 Token `color.background.navigation-selected`（浅色 `#e2e2de`、深色 `#393938`）和导航文字颜色，不使用整块黑白反转，键盘聚焦仍显示强化边界。语义状态色覆盖信息、成功、警告和错误，供 `StatusBadge`、`InlineMessage` 等组件统一使用；`color.business.lime|blue|amber|violet` 只作为工具、项目、分类与流程的身份色，红色不提供业务身份 Token。应用组件不得重新定义一套本地颜色、圆角或间距 Token。

工具目录和其他重复业务对象使用固定尺寸的短色条、小方块或进度段呈现身份色，不能用身份色大面积填充卡片、导航或普通操作按钮。当前目录映射为学习绿、娱乐紫、日历珊瑚橙、旅行/收藏琥珀；新增工具必须在目录注册处选择一项既有业务色或先扩展共享 Token，不能写入任意十六进制值。身份色可使用高饱和中间色阶；用于状态文字、图标或边框时必须改用与主题表面至少 `4.5:1` 对比度的语义色阶。业务色不得作为同类元素的默认前景色、整组背景或连续结构线铺开。

### 3.1.1 全局配色职责标准

颜色使用按“结构优先、语义其次、身份最小化”的顺序判断。默认界面在暂时移除所有业务色后，仍必须依靠中性色完成页面结构、文字层级和交互辨识；若去掉业务色后无法理解界面，说明业务色承担了不应承担的结构职责。

| 颜色职责 | Token 范围 | 允许表达 | 禁止表达 |
| --- | --- | --- | --- |
| 基础中性色 | `color.background.*`、`color.text.*`、`color.border.*` | 画布、表面、标题、正文、辅助文字、结构线、禁用和选中底 | 不适用 |
| 通用交互色 | `color.action.*`、`color.focus.ring` | 主/次命令、悬停、选中、键盘焦点和控件反馈；浅深主题均保持黑白灰 | 用业务色替代普通按钮、导航或页签状态 |
| 业务身份色 | `color.business.lime|blue|amber|violet` | 工具、项目、分类、流程或内容对象的小色标、小方块、圆点、进度段和受限边界 | 正文默认文字、整张卡片、整组日期、导航轨道、普通按钮或大面积背景 |
| 语义状态色 | `color.status.info|success|warning|error` | 信息、成功、警告、错误和危险操作的局部状态标记 | 业务身份、装饰、页面主题；不能成为唯一状态信号 |
| 专用工具强调色 | `color.accent.calendar` 等 | 工具内部少量且有明确定义的特殊状态，例如日历的今天、用户选中日期边界和笔记圆点 | 该工具所有默认文字、月份标题、整组网格或普通交互控件 |

同一色相不代表同一职责：`color.business.blue` 是对象身份，`color.status.info` 是状态语义，`color.accent.calendar` 是日历专用强调。组件只能消费与其职责匹配的语义 Token，不能因为颜色相近而互换。工具专用强调只允许作为工具内部的局部状态例外，不改变通用按钮、导航、页签和表单控件的中性色契约。

页面评审必须逐项检查默认、悬停、选中、焦点、禁用、加载、空、成功、警告、错误和权限拒绝状态；每种状态都要有文字、图标、形状、边界或位置等非颜色信号。业务色出现于连续同类元素时，应优先改为中性色，仅保留当前对象或当前状态的局部标记。所有业务色和状态色在浅色、深色主题中都必须满足与实际表面的 `4.5:1` 文本/图标对比度要求；大面积填充应使用对应的中性或语义浅层表面，而不是高饱和身份色。

### 3.2 动效规范

动效只用于确认操作已生效、说明内容切换和表达可量化进度，不承担装饰性或品牌氛围职责。`packages/design-tokens` 统一提供 `duration.fast`（120ms）、`duration.normal`（180ms）和 `easing.standard`；业务页面和组件不得写入局部时长、缓动曲线或任意延迟。

- 按钮、图标按钮、导航项和页签的颜色、边框与背景变化使用 `fast`；不使用缩放、弹跳或位移动画。
- 页签面板、折叠内容、原位消息和一次处理结果使用 `normal` 的透明度进入；不得让整个工作区滑入、滑出或改变滚动位置。
- 进度条只动画实际进度宽度；加载指示器可以旋转，但不得在无加载任务时持续运行。
- `prefers-reduced-motion: reduce` 下，动画与过渡时长均为 0，加载旋转和内容进入动画必须停止，状态仍以文字、焦点和语义控件完整表达。
- 设置中的动效诊断可将一个 `normal` 反馈拆成五段连续演示，便于观察实际 `180ms` 的进度过渡；该放大演示仅用于查看器，产品交互仍使用原始 Token。减少动效开启时仅展示最终状态并明确说明原因。
- 不允许持续背景动效、粒子/光晕、列表重排弹跳、自动消失的关键错误信息，或会导致文本和控件布局跳动的动效。

## 4. Layout and navigation

- The primary desktop layout uses a persistent, compact left navigation rail, a top contextual toolbar, and an uncluttered workspace.
- Desktop is the primary target: the shell baseline is a 960px minimum width by 640px minimum height, the workspace fills all available width, and the shell owns scrolling. Only long-form detail blocks may use a local readable width; they must not center or constrain the whole workspace. Narrow-window rules are a fallback below 900px and must not drive the desktop layout.
- 工具目录使用块状网格而非逐行清单：每个工具块只保留左侧身份色标记、工具名称、收藏与打开操作，不在卡片内重复显示分类或说明。全部工具页可在顶部显示合并且去重的“常用”区，常用标题下不使用分隔线；分类页和搜索结果只显示当前范围内的工具块，不混入跨分类的最近使用或收藏内容。
- 工具目录右侧工作区使用画布色作为连续底面；搜索输入框保留自身边界，搜索区域不额外绘制底部结构线；分类分区标题使用浅结构线（`color.border.default`），常用分区不显示标题下边线。分区图标使用中性辅助文字色，业务身份色使用工具名称左侧的固定小方块、进度段等小面积标记，不填充整张卡片。分区标题使用共享粗字重，与工具卡片标题形成明确层级，不使用深色粗线制造视觉分割。
- 工具目录采用严格两级分类：左侧只选择唯一的一级模块，主工作区在其下按二级分类依次显示分区标题和工具网格；每个工具只能出现在一个二级分类中，二级分类不能跨一级模块复用。没有工具的二级分类不显示，全部工具范围内的工具卡显示一级与二级分类名称。一级模块包含全部工具、学习、娱乐、工具和生活；生活域的“收藏”分类用于收藏类工具，当前包含“代代桌游馆”；当所选一级模块没有任何匹配工具时，使用共享 `EmptyState` 提供明确的查看全部工具下一步。
- “代代桌游馆”是收藏域的展示型工具：打开后首屏只保留馆名、馆藏统计和添加命令，下方以分类页签和自适应网格展示桌游信息卡片；每张卡片按“图片展示区 → 标题与简介 → 玩法元信息 → 编辑/删除操作”的层级排布，卡片使用统一的图片区域、正文最小高度和文字截断保持尺寸一致，图片展示区使用稳定的 `16:10` 比例并支持在添加/编辑弹窗中通过用户主动选择的图片文件上传封面，至少呈现玩法、人数、时长和难度，收藏使用图标按钮，显式保存与分类筛选位于同一控制行。添加和编辑使用公共 `Modal`、字段组件和保存命令，弹窗面板在遮罩内水平、垂直居中；删除使用带明确名称的危险图标命令，不把录入表单作为首屏主要布局。图片上传仅接受图片类型且限制 2MB，读取失败或格式不符时在原位显示错误。
- 打开工具后进入专注工作区：隐藏左侧分类导航，让工具使用完整窗口宽度；工具专注工具栏保留工具名、主题切换、设置和“← 工具台”。返回时必须释放工具会话并恢复之前的目录分类与搜索条件，不能把用户带到其他模块。
- 所有返回上一级的命令统一放在当前内容层级的左上角，并作为该层级的首个操作；日历工具将“← 工具台”与“← 年历/← 日历/← 日历待办”放在同一顶部操作行，其他工具的“← 工具台”位于专注工具栏最左侧。右侧只放置今天、设置和创建等同级功能命令。返回按钮保留完整 `aria-label`，可见文案不重复显示“返回”。
- 返回操作的顶部留白统一使用组件 Token `navigation.back-top-spacing`，当前解析值为 `8px`；工具栏和工具内容区仅复用该 Token 的顶部内边距，避免不同返回层级出现过大的不一致间距。
- Settings is a normal workspace route. The developer design-system viewer lives under Settings and is visually secondary to user settings; its component inventory and UI rules stay aligned with `packages/ui` and this specification.
- 标题层级保持简洁：同一界面已有明确主标题时，不再重复使用同义的 eyebrow、小标题或说明段落；eyebrow 仅在提供不可替代的上下文分类时保留，不能与紧邻标题重复表达同一信息。删除装饰性层级后，必须保留正确的 `aria-labelledby`/`aria-label` 区域名称和键盘焦点顺序。
- 工具台和工具专注工作区沿用同一规则：顶部工具栏的主标题负责表达当前页面或工具名称，目录筛选和工具内容不再重复渲染“工作区”类标题或介绍段落；只有常用/其他工具、日历月份、任务列等真正划分内容的区域保留标题。
- 日历待办的日历浏览页以日历为唯一主要工作区，不与待办/笔记并排；点击具体日期后进入独立日期详情页，详情页提供该日待办和笔记，顶部返回操作回到日历浏览页。日历浏览页与日期详情页都使用完整可用宽度，窄屏不改变页面边界。
- 当前设置页已完成主题、快捷键和开发者设计系统查看器。查看器按 `Token`、`主题对比`、`组件状态`、`动效`、`UI规范` 分页：使用紧凑表格呈现 Token、中文用途说明和当前解析值，保留横向滚动和键盘焦点；原始与语义颜色 Token 在当前主题下提供同一行的原生颜色选择器与十六进制输入，合法修改即时预览并在停止调整后持久化，恢复默认会清除当前主题覆盖且不额外提示；组件页先展示只含组件名称的公共组件目录，再以单一外框、细横竖分隔线和三列网格展示真实公共组件组合，组件分组使用短标签，不在卡片内重复类别和说明；`TextField` 可通过 `leadingIcon` 放置共享前置图标，`StatusBadge` 用小色标表达语义色，`ProgressBar` 默认使用信息珊瑚橙，`InlineMessage` 使用完整描边与状态色标，`EmptyState` 可使用 `framed` 与 `icon` 呈现虚线空状态；动效页读取真实 Token、按时间轴展示 120ms 与 180ms 的时长比例、展示当前系统减少动效状态，并通过共享 `InlineMessage` 和 `ProgressBar` 以五段 `180ms` 进度过渡演示反馈行为；规范页同步呈现本文件的 Token、布局、可访问性和状态约束。复制按钮使用图标、`title` 和 `aria-label`，复制结果通过 `FloatingNotice` 反馈。查看器中的组件示例必须来自公共组件，不得复制组件内部样式。
- `FloatingNotice` 是共享的短暂悬浮反馈：仅用于确认已完成或可逆操作，作为实时区域输出文字结果，并以窗口正中间的宽横条形式使用共享 `normal` 时长轻微浮入；它不得用于错误、权限拒绝或其他需要持续可见的信息，系统减少动效时直接显示最终状态。
- 日历待办使用“连续浏览 + 独立日期详情”模式：年历是日历浏览的上级页面，月历是点击具体月份后进入的下级页面，不使用页签切换；年历在当前年份前后连续展示 5 年，月历在当前月份前后连续展示 13 个月，两个视图的内容容器均支持上下滚动。月历通过顶部左侧的“返回年历”回到上级，顶部左侧的“今天”只定位日历到今天所在范围，不进入日期详情，周期打卡固定在顶部右侧；任意日期格点击后进入该日期详情页。日历工具的导航和功能命令统一使用带边界的共享普通按钮。日历按未开始、已完成分别标记日期任务数量，并在有已保存笔记的日期左下角显示无文字的彩色圆点徽标，徽标固定在日期格左下角，任务状态计数固定在右下角，日期格辅助名称同时表达“有笔记”。日期数字在格内水平、垂直居中；月历中的普通日期、月份标题和星期栏使用中性色，非当月日期进一步降级为页面背景和次要文字；年历当前月份只通过中性结构边界和浅层表面提示，月份标题与日期数字保持中性色；今天使用日历专用强调色、圆形强调底和更强字重，用户选中的日期只使用局部强调边界与数字强调。日期详情页的任务看板按两列呈现，普通待办项和周期同步项可拖拽到目标列；桌面 WebView 原生拖放不可用时使用鼠标/指针拖拽兜底，聚焦后可用方向键移动状态；周期同步项的拖拽和勾选会同步打卡完成日期。普通待办提供独立的红色危险删除按钮，周期同步项不在看板内提供删除，须在打卡管理中删除对应规则。任务看板下方提供按所选日期归属的多行“当日笔记”，用户点击“保存笔记”后写入本地；当日已有已保存笔记时显示启用状态下的“删除笔记”按钮，删除同样使用共享危险按钮并移除日期徽标，删除后清除当前日期草稿。保存空内容会清除该日笔记。打卡通过顶部独立按钮进入专门管理界面，不嵌套在每日待办下；管理界面使用名称、周期下拉和开始日期创建每日、每周或每月项目，并在每周周期显示星期选择、每月周期显示日期号选择。符合周期的实例同步显示在日历和日期详情页待办看板中，非周期日的复选框禁用，每个项目使用原生复选框和明确删除命令。
- 日历层级约束：今天在全年概览和月历中都使用日历专用珊瑚橙强调色、加粗字号和圆形强调底；该强调态不等同于选中态，也不使用选中边框。只有用户点击的日期才使用日历专用强调色内嵌边框和日期数字强调，与悬停态区分。年历当前月份只通过中性结构边界和浅层表面提示所在月份，月份标题、当月日期、跨月补位日期和星期栏均保持中性色；月历中的普通日期、月份标题和星期栏使用中性色，其他日期不因“当月”额外着色。年历浏览顶部不重复显示当前年份和前后周期导航；年历按年份分组且年份标题居中，每个年份标题位于月份网格上方，年份分组之间使用横向分隔线；月份按钮仅显示“X月”，年历月份沿用月历的标题、星期栏和日期网格边界语言，仅以三列紧凑网格降低密度。月历连续列表使用较小日期格，避免连续浏览时单月占用过多空间。日历专用强调色通过 `color.accent.calendar` 解析，在浅色和深色主题中保持珊瑚橙身份，并只按对比度调整明度。
- 月历返回按钮的当前可见文案遵循统一返回规则，显示为“← 年历”；文档中较早的“返回年历”描述仅保留为历史验收语义，不代表当前界面文案。
- 日历日期详情的日视图使用 `00:00–24:00`、15 分钟基础刻度的纵向时间轴。带有效 `startTime`/`endTime` 的待办以时间块呈现，未填写时间的待办进入任务看板；新增待办和时间编辑均使用共享 `TextField` 的本地时间输入，结束时间必须晚于开始时间。时间轴容器独立滚动，并提高每个 15 分钟槽的显示高度，让时间块顶部和高度始终与实际时间比例一致，同时保证短任务标题可读。时间块支持键盘聚焦、可访问名称和纵向拖动，拖动按 15 分钟吸附且限制在当天范围内；时间块只显示待办内容文本，不响应点击编辑。右侧任务卡片可内联展开时间输入，并在卡片内保存或取消；完成状态通过复选框与文字表达，不仅依赖颜色。
- 日期详情采用左右工作区：左侧承载全天时间刻度并直接显示带时间待办的时间块，右侧从上到下统一放置新增待办表单、任务看板和当日笔记；任务看板的“未开始/已完成”两列等宽占满右侧，并同时收纳带时间和不带时间的待办。桌面端双栏严格使用 1:1 比例，窄窗口在 900px 以下降级为纵向单列，保持时间轴和表单可用，不改变信息顺序或返回位置。时间轴标题行只显示当前日期与全天范围，不再重复显示日期或“时间安排”；右侧不重复提供“已安排时间”模块。
- 同一界面存在多个层级返回时，返回按钮必须在同一操作行连续排列并保持左侧起始位置；按钮统一使用共享次要命令样式和稳定尺寸。
- 返回按钮的背景、边界和点击区域应随“← 上一级名称”文本内容自适应，不使用固定最小宽度；年历和月历默认滚动位置应围绕今天所在日期，进入后将今天定位到可视区域中心附近。
- 日详情页应保持简洁：返回操作行下方和左侧日期标题上方不使用分隔线；右侧内容分区与时间轴内部刻度可按信息分组需要保留结构线。
- 每周和每月周期的规则选择使用可多选的原生复选框组：每周可勾选多个星期，每月可勾选多个日期号；至少保留一项选择后才能保存。
- 周期打卡管理进入后只显示独立卡片网格画廊，不显示常驻创建表单或空状态说明；网格首项固定为带加号的“添加打卡”卡片，项目卡片在桌面端紧凑多列排列、窄屏下自动单列。点击加号或项目卡片主体打开弹窗，分别用于新增或编辑；点击弹窗周围遮罩可关闭；完成复选框不触发编辑，删除按钮固定在项目卡片右下角并使用共享红色危险按钮。
- 删除等破坏性命令应优先使用共享 `Button` 的红色危险变体，并基于错误语义 Token 保留可读文字和明确的按钮边界，不以颜色单独表达含义。
- 设置入口统一放在顶部工具栏主题切换的右侧，不再作为工具台左侧分类页签；设置以随视口宽高同比适配、占用大部分可用工作区的宽屏模态弹窗打开，支持关闭按钮、点击弹窗外部和 `Escape` 关闭，内容区独立滚动，并在弹窗内容边缘保留稳定内边距，弹窗内保留设置页签的键盘与焦点反馈。
- Page sections are unframed layouts. Use cards only for repeated content, dialogs, or truly bounded working surfaces.
- Do not nest cards or use oversized hero typography in operational screens.

调试定位补充（D-053）：最近的 `data-debug-source` 声明优先于父级区域，格式为 `路径:行`（需要时可带列号），单个输入、按钮或文本节点可以精确定位到一行源码；没有声明时才显示 DOM 片段与缺失提示。

## 5. Components and interactions

Shared components are the default. Before creating a new one, verify that an existing component cannot meet the interaction requirement.

- Use icon buttons for familiar compact actions and provide tooltips for unfamiliar icons.
- Use text buttons only for explicit commands; use toggles, checkboxes, sliders, selects, tabs, and menus for their native interaction patterns.
- `Button` 只表示一次性命令（例如保存、打开或删除）；`ToggleButton` 表示可保持的独立二态状态（例如调试或模式开关），必须受控传入 `pressed` 并输出 `aria-pressed`。互斥状态选择（例如浅色/深色主题、筛选和处理方式）使用公共 `ChoiceGroup`，由同一组 `aria-pressed` 按钮表达当前值，不输出 `tablist` 语义；页签切换使用 `Tabs`、`HorizontalTabs` 或 `VerticalTabs`，由 `tablist`/`tab`（以及 `Tabs` 的 `tabpanel`）表达内容或同级导航切换。二态开关、状态选择组和页签不可互相替代。状态按钮使用独立的背景、边界和状态圆点与普通命令按钮区分；选中样式和可访问状态必须同步更新，不能仅靠点击后的临时提示表达。
- Buttons and controls have stable dimensions across loading, hover, selected, disabled, and error states.
- Every interactive element supports keyboard navigation, visible focus, disabled behavior, and accessible labeling.
- Dialogs trap focus, have an explicit close action, and do not conceal destructive consequences.
- Loading, empty, error, offline, and permission-denied states are part of every applicable component and tool workflow.

`FloatingNotice` 用于自动消失的成功或可逆操作确认；`InlineMessage` 保留在原位，用于输入错误与需要用户继续处理的信息。两者均为公共组件，业务模块不得自行定义悬浮提示样式或动效。

设置中的组件展厅必须使用真实公共组件展示组合控件：页签、选项组、开关字段、设置行、下拉选择、步进输入、折叠面板和空内容状态至少各有一个可交互示例，并与按钮、图标按钮、输入框、状态标签、进度条、信息/错误消息状态并列展示。

学习验证工具至少提供可编辑状态、显式保存操作和保存成功状态；独立存储不应在用户尚未确认保存时悄悄覆盖草稿。

娱乐验证工具至少提供候选活动选择、显式保存操作和保存成功状态；候选活动使用公共 `ChoiceGroup`，以按钮的 `aria-pressed` 暴露当前选中项，未点击保存前不得写入娱乐工具的本地命名空间。重新进入工具时应显示已保存选择，关闭和再次打开不得影响其他分类工具的状态。

文本工作台已从桌面“工具”目录下架，不提供目录入口或动态加载能力；其遗留源码不构成当前产品功能。

需要受限能力的工具必须在用户触发具体操作时显示清晰的授权请求，说明本次访问的能力和对象；用户拒绝、取消或系统不可用时使用 `InlineMessage` 给出文字原因和可恢复的下一步，不得把授权失败伪装成加载状态，也不得仅用颜色表达结果。

### 5.1 已实现基础组件

`packages/ui` 的公共组件为 `Button`、`ToggleButton`、`IconButton`、`NavigationItem`、`TextField`、`TextAreaField`、`EmptyState`、`InlineMessage`、`Tabs`、`HorizontalTabs`、`VerticalTabs`、`ChoiceGroup`、`ToggleField`、`SettingRow`、`SelectField`、`StepperField`、`StatusBadge`、`ProgressBar` 与 `Disclosure`。`Button` 只承载一次性命令，支持主、次、危险红色三种带边界操作层级以及禁用、加载状态；`ToggleButton` 承载受控二态状态并通过 `aria-pressed` 与选中样式表达当前值；危险红色变体专用于删除等破坏性命令；`IconButton` 必须提供统一尺寸、提示、可访问名称和按下状态；`NavigationItem` 组合紧凑导航尺寸、图标标签和 `aria-current` 当前页面语义；`TextField` 支持可选 `leadingIcon` 且必须使用可见标签，`TextAreaField` 和 `SelectField` 同样必须使用可见标签并在存在错误时设置 `aria-invalid` 与 `alert`；`EmptyState` 必须给出明确下一步，并可用 `framed` 与 `icon` 表达虚线空状态；`InlineMessage` 用于原位信息或可恢复错误，以完整边框和状态色标表达语义；`Tabs` 是带面板的受控页签组件，`HorizontalTabs` 和 `VerticalTabs` 是不带面板的横向/竖向页签选择控件，页签项可组合图标与标签，均输出 `tablist`/`tab` 语义、选中状态和方向键、`Home`/`End` 导航；`ChoiceGroup` 是互斥状态选择组，使用独立边界和 `aria-pressed` 按钮，不输出 `tablist`；`ToggleField` 组合原生复选框、可见标签和说明关联；`SettingRow` 组合设置项说明与控件并在窄屏下纵向排列；`StepperField` 组合数值输入、增减按钮和边界约束；`StatusBadge` 默认用中性边框和语义小色标表达状态，`ProgressBar` 默认使用信息珊瑚橙并支持语义色调，`Disclosure` 提供可展开内容。组件的焦点、禁用、加载、错误、选中、动效和响应式样式只通过 `packages/design-tokens` 的语义和组件 Token 实现。

`HorizontalTabs` 与 `VerticalTabs` 共享同一套无外框页签栏视觉：外层不绘制边框、背景或额外内边距，页签项以整行文字排列；未选中项使用辅助文字色，选中和悬停使用 `color.background.selected` 浅灰表面与主文字色，选中项使用共享粗字重和 `4px` 圆角。横向页签按内容宽度排列，竖向页签填满父容器；焦点轮廓、禁用透明度和方向键/`Home`/`End` 行为保持不变。

`ChoiceGroup` 与页签栏保持明确的视觉边界：选项组使用带边界的紧凑按钮，未选中使用表面色，选中使用主文字色填充并以反色文字呈现；它只改变一个设置、筛选或处理模式的当前值，不承载面板或路由。`ToggleButton` 继续表示独立二态开关，使用状态圆点、`aria-pressed` 和更强的按压态；单个开关、互斥选项组和页签栏不得共用同一组件样式。

Modal 是公共复合控件，必须使用原生 modal 语义（`showModal()`）或等价回退：遮罩点击与 `Escape` 关闭，键盘焦点限制在弹窗内，关闭后焦点恢复到打开弹窗的控件。设置和工具内编辑弹窗统一复用该组件，不得使用仅设置 `open` 属性的非模态对话框。

公共组件目录中的 `Modal` 与 `packages/ui/src/Modal.tsx` 保持同步，设计系统查看器必须直接读取目录契约展示其焦点、关闭和遮罩行为。

## 6. Typography and icons

### 6.1 旅行笔记视觉方向

旅行笔记允许在共享 Token、组件和无障碍约束内使用更有情绪的内容编排：旅行封面使用真实照片作为内容入口，单次旅行详情以连续时间线表达日期顺序，标题统一使用共享无衬线字体，并通过字号和字重建立层次，时间和金额使用等宽字体。照片只承担回忆入口，不替代记录正文；操作按钮继续使用共享 `Button`，快速记录和新建旅行使用明确的图标加文字。动效仅用于章节展开和保存反馈，并遵守减少动效设置。工具不得新增独立主题色或覆盖共享 Token；旅行与条目强调色只能映射到 `color.business.*`，不得以红色作为业务色。

旅行笔记的搜索只过滤当前旅行的标题、正文和地点，并在无匹配时复用 `EmptyState` 提供下一步；费用入口使用共享 `Modal` 和 `SelectField`，金额显示必须带货币单位；回顾视图使用共享 `HorizontalTabs` 的受控 `tablist` 切换，不复制时间线业务数据。

排版使用 `packages/design-tokens` 的共享层级：页面标题使用 `typography.size.page-title`（32px/40px），工具标题使用 `typography.size.tool-title`（24px/32px），分区标题使用 `typography.size.section-title`（16px/24px），正文使用 `typography.size.body`（14px/20px），辅助文字使用 `typography.size.caption`（12px/16px），数据与日期文字使用 `typography.size.data`（13px）。展示与正文拉丁字形使用 `typography.font-family.sans` 中的 `Archivo`，标签、时间和金额使用 `typography.font-family.mono` 中的 `DM Mono`；中文使用同一字体栈中的系统中文回退。页面不得以间距 Token 代替字号或行高，也不得在业务样式中写入新的字号层级或随视口缩放的字号。

桌面壳层复用公共组件：顶部工具栏的一次性设置/工具操作使用 `Button`，主题互斥状态选择使用 `ChoiceGroup`，调试状态使用 `ToggleButton`，顶部搜索使用带共享图标前缀的 `TextField`，搜索区占满目录可用宽度并在窄窗口下随容器收缩；收藏使用带 `title` 和 `aria-label` 的图标按钮并通过 `aria-pressed` 暴露状态。工具台左侧主导航使用 `VerticalTabs` 的键盘与 ARIA 契约，但视觉上采用示例工作台的主题适配轨道：导航轨道使用稳定的 `200px` 宽度，浅色主题为浅色左栏、深色主题为深色左栏，品牌标识与产品字标位于顶部，导航分组标题和一级模块列表无额外页签容器，一级模块使用纯文字整行导航，当前项使用 `color.background.navigation-selected` 中性表面表达；底部可显示真实的工具注册统计。二级分类在主工作区作为分区标题呈现。设置以模态弹窗呈现。工具目录使用稳定尺寸的可聚焦工具块网格，常用工具不会与目录重复；空目录使用 `EmptyState`，确保键盘焦点和浅色/深色主题下的可读性一致。

当前日历待办存储契约以 `{ version: 5, todos: TodoItem[], checkIns: CheckInItem[], notes: DailyNote[] }` 为准：`TodoItem` 的 `startTime`/`endTime` 为可选本地 `HH:mm` 时间区间，结束时间必须晚于开始时间；`CheckInItem` 必须包含 `frequency`（`daily`/`weekly`/`monthly`）和 `startDate`，并保存完成日期；`DailyNote` 以日期、笔记内容和更新时间保存，每日最多一条且空内容不存储。读取兼容旧数组、版本 1 的 `{ items }`、版本 2 打卡记录以及版本 3、版本 4 数据，旧任务的进行中状态迁移为未开始且无时间任务进入未安排区；无效日期、空标题、无效创建时间、无效状态或非法时间区间会被忽略。任务按日期归属并使用未开始、已完成状态；周期实例是由打卡项目派生的待办视图，不重复写入任务数组，拖拽或勾选操作只更新任务状态或对应打卡完成日期。普通待办可独立删除，删除不影响当天笔记或周期打卡规则。任务、打卡与笔记保存由 `FloatingNotice` 短暂悬浮确认。

设置页中的全局快捷键使用可见标签的原生复选框表达启用状态；注册失败或宿主不支持时通过 `InlineMessage` 提供文字反馈，不能只以禁用控件或颜色表达原因。

- Use a system font stack suitable for Windows and macOS.
- Do not scale font sizes with viewport width and do not use negative letter spacing.
- Match heading scale to context: compact panels and sidebars use compact headings.
- Use the shared icon set. Do not draw ad hoc SVG icons when the icon set contains an appropriate symbol.
- Icons alone must have a tooltip and an accessible name.

## 7. Developer design-system viewer

The viewer must show the following and may edit validated primitive and semantic color values:

- token name, token layer, Chinese usage description, resolved value, and active-theme value
- light/dark theme comparison
- component variants, sizes, interaction states, and disabled/loading examples
- a direct copy action for token names and values

Primitive and semantic color edits are scoped to the active light or dark theme, persisted by the desktop shell, and applied through the shared design-token CSS variables. The viewer must provide a visible restore-default command and an inline confirmation; invalid hex values must remain local draft text and must not be applied.

This facility exists to detect visual drift during development. It must be generated from the actual token and component sources, never maintained as a disconnected documentation mockup. The component inventory and synchronized guideline summary are exposed by `packages/ui` through `uiComponentCatalog` and `uiGuidelineGroups`.

## 8. Review checklist

- Uses shared tokens rather than literal visual values.
- Renders correctly in both themes.
- Has no text overlap or layout shift in ordinary dynamic states.
- Has keyboard, focus, loading, empty, error, and permission-denied coverage as applicable.
- 遵守动效时长、标准缓动和减少动效规则；动态状态不会造成布局跳动。
- Uses shared components or documents why a new shared component is necessary.
- Keeps colors, radius, spacing, iconography, and control behavior consistent with this document.

工具调试模式属于工具主机和专注工作区的开发者诊断覆盖层：顶部主题切换旁提供带图标的“调试”按钮直接开关；默认快捷键为 `Ctrl + Alt + 0`（macOS 使用对应的 Command/Option），设置页提供可聚焦的快捷键录入和启用开关，录入失败或注册冲突必须以文字反馈说明，开关本身不弹出提示。每个界面底部提供紧凑的运行输出台，使用共享边界、间距和文字 Token，显示可清空的运行日志，不使用固定颜色表达状态。输出台顶部同时提供带终端图标的“输出台”二态按钮，默认显示，可通过按钮或独立快捷键 `Ctrl + Alt + 1`（macOS 使用对应的 Command/Option）显隐；隐藏不停止日志采集，关闭工具时恢复显示并清空当前会话日志。输出台快捷键可在设置页聚焦录入、启用或停用，失败与冲突使用文字反馈。调试覆盖层的区域框、控件框和文本框使用现有信息、警告、成功语义 Token，不新增孤立颜色；框体和源码浮窗使用共享间距、边界、圆角、层级 Token，浅色/深色主题均保持可读。覆盖层悬浮框不拦截指针，点击工具元素后显示带明确标题、类型、代码位置和源码内容的浮动面板；按 `Escape` 退出调试模式。工具通过 `data-debug-*` 元数据声明源码位置，未声明时必须明确显示缺失状态而不能伪造位置。调试状态仅在当前工具会话生效，关闭工具时释放覆盖层。
